## 1. 迁移目标

在保持现有图谱问答能力可用的情况下，逐步完成：

```text
Streamlit 单页
-> Vue 3 工作台

Engine 直接调用
-> 应用服务 + Tool Registry + Skill Registry

Web-only
-> Web + 本地 MCP
```

核心原则是渐进式替换，不做一次性全量重写。

## 2. 迁移约束

- 现有 `/api/v1` 在迁移期保持可用。
- 现有 `GraphQAEngine`、`CypherGuard` 和证据审核不得被绕开。
- Vue 页面达到功能对齐前，Streamlit 不删除。
- 每次迁移只替换一个明确边界。
- Neo4j 数据模型不由本次重构修改。
- 数据库写入、在线训练和远程 MCP 不在本次范围。
- 出现无法自动验证的契约变化时暂停迁移。

## 3. 目标仓库结构

```text
.
├── frontend/                    # Vue 3 + Vite
├── graph_qa/
│   ├── application/             # 新增应用服务
│   ├── tools/                   # Tool Registry
│   ├── skills/                  # Skill Registry
│   ├── interfaces/
│   │   ├── api/                 # API v2
│   │   └── mcp/                 # stdio MCP
│   ├── agents/                  # 保留并渐进整理
│   ├── infrastructure/          # 渐进迁移适配器
│   └── ...                      # 现有模块暂保留
├── skills/domain/               # Skill YAML
├── tests/
├── docs/
└── compose.demo.yml
```

阶段 1 不移动现有模块。先增加新包和适配层，确认稳定后再迁移文件。

## 4. 分阶段实施

### 阶段 0：设计与契约冻结

预计：2～3 天。

交付：

- 需求规格。
- 技术与架构设计。
- 本迁移方案。
- 项目验收方案。
- 架构图。

退出条件：

- Vue、单机演示、MCP stdio 首版范围确认。
- API v2 公共字段冻结。
- Tool 和 Skill 范围冻结。

### 阶段 1：应用层与 Tool Registry

预计：7～10 天。

交付：

- `application/` 基础服务。
- `tools/contracts.py`。
- `tools/registry.py`。
- `tools/executor.py`。
- 前四个只读 Tool。
- 实体 ID 映射。
- 应用层单元测试。

首批 Tool：

- `resolve_entity`
- `query_entity_facts`
- `query_neighbors`
- `find_evidence_paths`

退出条件：

- Tool 契约测试通过。
- 输出不包含原始 Cypher 行。
- 错误和超时稳定。
- 现有 Engine 可作为 Tool 后端复用。

### 阶段 2：API V2

预计：5～7 天。

交付：

- `/api/v2/qa`
- `/api/v2/qa/stream`
- `/api/v2/entities/search`
- `/api/v2/entities/{id}/neighbors`
- `/api/v2/paths`
- `/api/v2/tools`
- OpenAPI 描述。
- 匿名演示会话与配额。

退出条件：

- V1 契约不回归。
- V2 OpenAPI 可生成 TypeScript 类型。
- SSE 事件与 V1 核心字段一致。
- 浏览器不接触静态 API Key。

### 阶段 3：Vue 工程与问答页

预计：7～10 天。

交付：

- `frontend/` Vite 工程。
- 路由、布局、主题和基础组件。
- 证据问答页。
- SSE 阶段时间线。
- 回答、证据、来源和审核卡片。
- 错误与降级状态。

退出条件：

- 问答页达到 Streamlit 核心能力。
- 桌面和手机宽度可操作。
- Vue 组件和 E2E 测试通过。

### 阶段 4：图谱探索与对比

预计：7～10 天。

交付：

- 实体搜索。
- 一跳邻居图。
- 关系筛选。
- 受控路径图。
- 节点与证据联动。
- 药材/方剂对比页。

退出条件：

- 图谱邻域最多显示 50 节点。
- 多跳路径与逐跳证据一致。
- 对比结果可追溯来源。
- 不发生全图渲染。

### 阶段 5：证据审核与报告

预计：4～6 天。

交付：

- `audit_claims` Tool。
- `compare_entities` Tool。
- 核验状态页。
- Markdown 报告导出。
- 报告不包含密钥和隐藏推理。

退出条件：

- 每项 claim 可对应证据。
- 未支持 claim 被明确标识。
- 报告字段完整且可复现。

### 阶段 6：Skill Registry 与领域 Skill

预计：5～7 天。

交付：

- Skill YAML Schema。
- Skill Registry。
- 确定性 Skill Executor。
- 三个领域 Skill。
- 每个 Skill 固定评测。

退出条件：

- Skill 只能调用白名单工具。
- Tool 调用次数和超时有硬限制。
- Skill 不通过自由 Prompt 绕开证据策略。

### 阶段 7：MCP stdio V1

预计：4～6 天。

交付：

- stdio MCP Server。
- Schema、评测、工具和 Skill Resources。
- V1 Tool 映射。
- MCP 客户端配置示例。
- MCP 错误和未授权测试。

退出条件：

- 本地 MCP 客户端可发现工具和资源。
- 调用结果与 Web API 证据语义一致。
- MCP 进程不直接连接 Neo4j。
- 不开放公网无认证 MCP。

### 阶段 8：演示部署与切换

预计：5～7 天。

交付：

- `compose.demo.yml`。
- Vue 静态资源。
- Nginx/HTTPS。
- 匿名会话、限流和日预算。
- 健康检查、日志和自动重启。
- Streamlit 与 Vue 并行可切换。

退出条件：

- 公网演示链接可用。
- 24 小时连续运行。
- 固定演示问题通过。
- 外部模型失败可降级。
- 无密钥进入浏览器或镜像。

## 6. 前端迁移顺序

页面按业务价值迁移：

1. 证据问答。
2. 图谱探索。
3. 实体对比。
4. 审核与评测。
5. 开发者接入。

不按组件类型迁移，避免出现大量孤立组件但页面不可用。

每个页面必须完成：

- 加载状态。
- 空状态。
- 无证据状态。
- 模型降级状态。
- 手机布局。
- E2E 用例。

## 7. 契约迁移

### 7.1 API

```text
v1 保留
v2 新增并与 Vue/MCP 使用
v2 稳定后再评估 v1 弃用
```

### 7.2 TypeScript 类型

- 从 FastAPI OpenAPI 生成基础类型。
- 对 SSE 事件手写判别联合类型。
- 禁止前端重复手写后端枚举。

### 7.3 版本号

- API `schema_version` 保持 `1.0`，直到发生破坏性变化。
- Tool 和 Skill 各自使用独立语义版本。
- MCP Tool 描述必须包含 Tool 版本。

## 8. 数据与配置迁移

- Neo4j 数据不变。
- Redis 键在演示环境使用独立前缀。
- 旧 API Key 继续用于 V1 和 CLI。
- Vue 使用匿名短期 Cookie。
- `.env` 不提交，示例同步更新。
- 外部模型和数据库凭据只存在于服务端 Secret。

## 9. 测试与 CI 迁移

每个阶段都必须增加测试，不允许最后统一补测试。

PR/分支检查：

- Python 单元测试。
- 前端 lint、类型检查和组件测试。
- OpenAPI 契约测试。
- MCP Schema 测试。
- 关键页面 Playwright 测试。

真实依赖测试继续通过显式环境变量启用：

- Neo4j。
- Redis。
- 外部模型。

## 10. 回滚策略

| 阶段 | 回滚方式 |
| --- | --- |
| Tool/API v2 | 关闭 v2 路由，继续使用 v1 |
| Vue | 重新切回 Streamlit 入口 |
| Skill | 从 Skill Registry 移除配置 |
| MCP | 停止 stdio 进程，不影响 Web |
| Demo 部署 | 回退上一镜像版本 |
| 数据层 | 不修改图结构，无需数据回滚 |

每个阶段使用独立 commit，合并后保留可回退点。

## 11. 分支与提交策略

- 从 `main` 创建短生命周期分支。
- 设计、后端契约、前端、Skill、MCP、部署分别提交。
- 不使用 `git add -A`。
- 不在功能分支混合无关格式化和重构。
- 合并后删除短生命周期分支。

## 13. 关键风险

| 风险 | 控制 |
| --- | --- |
| Vue 学习导致延期 | 使用 Element Plus 和固定页面模板 |
| 旧页面与新 API 漂移 | v2 契约测试，v1 保持兼容 |
| Tool 范围失控 | V1 最多 7 个 |
| Skill 过度自治 | 固定工具白名单和调用上限 |
| MCP 安全面扩大 | 仅 stdio，远程延后 |
| 外部模型不稳定 | 固定演示场景、缓存和降级 |
| 医疗内容风险 | 免责声明、来源披露和人工审核 |
| 部署成本 | 单机、单 worker、每日预算 |

## 14. 迁移完成定义

- Vue 四条主链路可用。
- API v2 与 Tool 契约稳定。
- 本地 MCP 可用。
- Streamlit 仍可在回滚窗口内使用。
- 现有查询安全、多轮和证据审核不回归。
- 公网演示持续运行 24 小时。
- 验收文档中的 P0 项全部通过。
