## 1. 迁移目标

在保持现有图谱问答能力可用的情况下，逐步完成：

```text
Streamlit 单页
-> Vue 3 工作台

Engine 直接调用
-> 应用服务 + Tool Registry + Skill Registry

Web-only
-> Web + 本地 MCP
```

核心原则是渐进式替换，不做一次性全量重写。

V1 系列分为两个发布版本：

- V1.0：应用服务、只读 Tool、API V2、证据问答、图谱探索和首次公网部署。
- V1.1：实体对比、报告、领域 Skill、本地 stdio MCP 和完整质量签收。

## 2. 迁移约束

- 现有 `/api/v1` 在迁移期保持可用。
- 现有 `GraphQAEngine`、`CypherGuard` 和证据审核不得被绕开。
- Vue 页面达到功能对齐前，Streamlit 不删除。
- 每次迁移只替换一个明确边界。
- Neo4j 数据模型不由本次重构修改。
- 数据库写入、在线训练和远程 MCP 不在本次范围。
- 出现无法自动验证的契约变化时暂停迁移。

阶段 1 不移动现有模块。先增加新包和适配层，确认稳定后再迁移文件。

## 4. 分阶段实施

### 阶段 0：设计与契约冻结

预计：2～3 天。

交付：

- 需求规格。
- 技术与架构设计。
- 本迁移方案。
- 项目验收方案。
- 架构图。

退出条件：

- V1.0 与 V1.1 发布范围、阻塞项和非目标确认。
- 首次部署节点调整到 V1.0 核心页面完成后。
- API v2 公共字段冻结。
- V1.0 四个 Tool 和 V1.1 Skill 范围冻结。

### 阶段 1：应用层与 Tool Registry

预计：7～10 天。

交付：

- `application/` 基础服务。
- `tools/contracts.py`。
- `tools/registry.py`。
- `tools/executor.py`。
- 前四个只读 Tool。
- 实体 ID 映射。
- 应用层单元测试。

首批 Tool：

- `resolve_entity`
- `query_entity_facts`
- `query_neighbors`
- `find_evidence_paths`

退出条件：

- Tool 契约测试通过。
- 输出不包含原始 Cypher 行。
- 错误和超时稳定。
- 现有 Engine 可作为 Tool 后端复用。

### 阶段 2：API V2

预计：5～7 天。

交付：

- `/api/v2/qa`
- `/api/v2/qa/stream`
- `/api/v2/entities/search`
- `/api/v2/entities/{id}/neighbors`
- `/api/v2/paths`
- `/api/v2/tools`
- OpenAPI 描述。
- 匿名演示会话与配额。

退出条件：

- V1 契约不回归。
- V2 OpenAPI 可生成 TypeScript 类型。
- SSE 事件与 V1 核心字段一致。
- 浏览器不接触静态 API Key。

### 阶段 3：Vue 工程与问答页

预计：7～10 天。

交付：

- `frontend/` Vite 工程。
- 路由、布局、主题和基础组件。
- 证据问答页。
- SSE 阶段时间线。
- 回答、证据、来源和审核卡片。
- 错误与降级状态。

退出条件：

- 问答页达到 Streamlit 核心能力。
- 桌面和手机宽度可操作。
- Vue 组件和 E2E 测试通过。

### 阶段 4：图谱探索

预计：5～7 天。

交付：

- 实体搜索。
- 一跳邻居图。
- 关系筛选。
- 受控路径图。
- 节点与证据联动。

退出条件：

- 图谱邻域最多显示 50 节点。
- 多跳路径与逐跳证据一致。
- 不发生全图渲染。

### 阶段 5：V1.0 首次演示部署

预计：5～7 天。

交付：

- `compose.demo.yml`。
- Vue 静态资源。
- Nginx/HTTPS。
- 匿名会话、每 IP 限流、全局并发和模型预算硬上限。
- 健康检查、日志、自动重启和基础运行手册。
- Streamlit 与 Vue 并行回滚入口。
- 实时、缓存和确定性降级模式标识。

退出条件：

- 公网演示链接可用。
- 证据问答、实体搜索、一跳邻居和受控路径通过真实浏览器测试。
- 未知实体、无证据、无来源和模型异常有明确状态。
- 无密钥进入浏览器或镜像。
- V1.0 固定演示问题通过，未执行的真实依赖项不得标记为通过。

### 阶段 6：对比、核验与报告（V1.1）

预计：6～8 天。

交付：

- `compare_entities` Tool。
- `audit_claims` Tool 的对外封装。
- 药材/方剂对比页。
- 独立核验状态页。
- Markdown 报告导出。
- 报告不包含密钥和隐藏推理。

退出条件：

- 对比结果可追溯属性和关系来源。
- 每项 claim 可对应证据，未支持 claim 被明确标识。
- 报告字段完整且可复现。

### 阶段 7：Skill Registry 与领域 Skill

预计：5～7 天。

交付：

- Skill YAML Schema。
- Skill Registry。
- 确定性 Skill Executor。
- 三个领域 Skill。
- 每个 Skill 固定评测。

退出条件：

- Skill 只能调用白名单工具。
- Tool 调用次数和超时有硬限制。
- Skill 不通过自由 Prompt 绕开证据策略。

### 阶段 8：MCP stdio V1.1

预计：4～6 天。

交付：

- stdio MCP Server。
- Schema、评测、工具和 Skill Resources。
- V1.1 Tool 映射。
- MCP 客户端配置示例。
- MCP 错误和未授权测试。

退出条件：

- 本地 MCP 客户端可发现工具和资源。
- 调用结果与 Web API 证据语义一致。
- MCP 进程不直接连接 Neo4j。
- 不开放公网无认证 MCP。

### 阶段 9：V1.1 集成与最终验收

预计：4～6 天。

交付：

- V1.1 功能集成和回归。
- 来源数据授权与真实性检查结论。
- 完整固定集、人工审核和失败项汇总。
- 更新后的公网镜像和上一镜像回滚点。

退出条件：

- V1.1 功能达到验收方案对应门禁。
- 24 小时连续运行通过。
- 固定演示问题、异常场景和外部模型失败降级通过。
- 所有未执行项明确记录并解决；标记为 `blocked` 或 `not_evaluated` 不能替代通过结果。

## 6. 前端迁移顺序

页面按业务价值迁移：

1. V1.0 证据问答与审核联动。
2. V1.0 图谱探索与受控路径。
3. V1.0 开发者入口最小版。
4. V1.1 实体对比。
5. V1.1 独立核验与报告。
6. V1.1 Skill、MCP 和完整开发者入口。

不按组件类型迁移，避免出现大量孤立组件但页面不可用。

每个页面必须完成：

- 加载状态。
- 空状态。
- 无证据状态。
- 模型降级状态。
- 手机布局。
- E2E 用例。

## 7. 契约迁移

### 7.1 API

```text
v1 保留
v2 新增并与 Vue、Tool 和 V1.1 MCP 使用
v2 稳定后再评估 v1 弃用
```

### 7.2 TypeScript 类型

- 从 FastAPI OpenAPI 生成基础类型。
- 对 SSE 事件手写判别联合类型。
- 禁止前端重复手写后端枚举。

### 7.3 版本号

- API `schema_version` 保持 `1.0`，直到发生破坏性变化。
- Tool 和 Skill 各自使用独立语义版本。
- MCP Tool 描述必须包含 Tool 版本。

## 8. 数据与配置迁移

- Neo4j 数据不变。
- Redis 键在演示环境使用独立前缀。
- 旧 API Key 继续用于 V1 和 CLI。
- Vue 使用匿名短期 Cookie。
- `.env` 不提交，示例同步更新。
- 外部模型和数据库凭据只存在于服务端 Secret。
- 来源章节、页码和原文增强需要独立数据治理、授权检查与兼容方案，不在 V1.0 通过修改 DTO 实现。

## 9. 测试与 CI 迁移

每个阶段都必须增加测试，不允许最后统一补测试。

PR/分支检查：

- Python 单元测试。
- 前端 lint、类型检查和组件测试。
- OpenAPI 契约测试。
- V1.1 MCP Schema 测试。
- 关键页面 Playwright 测试。

真实依赖测试继续通过显式环境变量启用：

- Neo4j。
- Redis。
- 外部模型。

## 10. 回滚策略

| 阶段 | 回滚方式 |
| --- | --- |
| Tool/API v2 | 关闭 v2 路由，继续使用 v1 |
| Vue | 重新切回 Streamlit 入口 |
| Skill | 从 Skill Registry 移除配置 |
| MCP | 停止 stdio 进程，不影响 Web |
| V1.0 Demo 部署 | 回退上一镜像版本 |
| V1.1 增强能力 | 关闭对比、报告、Skill 和 MCP 入口，保留 V1.0 Web |
| 数据层 | 不修改图结构，无需数据回滚 |

每个阶段使用独立 commit，合并后保留可回退点。

## 11. 分支与提交策略

- 从 `main` 创建短生命周期分支。
- 设计、后端契约、前端、Skill、MCP、部署分别提交。
- 不使用 `git add -A`。
- 不在功能分支混合无关格式化和重构。
- 合并后删除短生命周期分支。

## 12. 预计周期

单人全职串行开发：

- 阶段 0：2～3 天。
- V1.0 阶段 1～5：29～41 个工作日。
- V1.1 阶段 6～9：19～27 个工作日。

V1.0 目标约 **6～8 周**，V1.1 再增加约 **4～6 周**。这些是规划区间，不替代实际完成情况和验收记录。

首次部署位于 V1.0 阶段 5，不再等待 V1.1 全部完成。若准备时间紧，V1.1 功能可以按对比与报告、Skill、MCP 的顺序单独交付。

## 13. 关键风险

| 风险 | 控制 |
| --- | --- |
| Vue 学习导致延期 | 使用 Element Plus 和固定页面模板 |
| 旧页面与新 API 漂移 | v2 契约测试，v1 保持兼容 |
| 首发范围失控 | V1.0 只阻塞四个 Tool 和核心 Web 链路 |
| Tool 范围失控 | V1 系列最多 7 个 |
| Skill 过度自治 | 固定工具白名单和调用上限 |
| MCP 安全面扩大 | 仅 stdio，远程延后 |
| 外部模型不稳定 | 固定演示场景、缓存和降级 |
| 医疗内容风险 | 免责声明、来源披露和人工审核 |
| 来源数据不足 | 不补造章节、页码或原文；来源增强先做数据治理 |
| 数据授权不明 | 公网发布前完成来源和再分发检查 |
| EntityId 随改名变化 | 明确内容派生 ID 限制，未来稳定 ID 做兼容迁移 |
| 部署成本 | 单机、单 worker、每日预算 |

## 14. 分版本迁移完成定义

### 14.1 V1.0 完成定义

- API v2 与 Tool 契约稳定。
- Vue 证据问答、图谱探索、证据审核和最小开发者入口可用。

- V1.0 完成定义继续满足。
- 实体对比、报告、三个领域 Skill 和本地 MCP 可用。

- 现有查询安全、多轮和证据审核不回归。

- 验收文档中的 V1.1 项全部有真实通过结果，不存在未解决的 `blocked` 或 `not_evaluated` 门禁项。
