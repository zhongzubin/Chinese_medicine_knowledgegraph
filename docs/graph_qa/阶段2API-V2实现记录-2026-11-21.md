## 3. V2 路由

```text
POST /api/v2/qa
POST /api/v2/qa/stream
POST /api/v2/entities/search
GET  /api/v2/entities/{entity_id}
GET  /api/v2/entities/{entity_id}/neighbors
POST /api/v2/paths
GET  /api/v2/tools
GET  /api/v2/schema/summary
```

REST 响应统一使用 `ApiEnvelope<T>`。SSE 保留 V1 的公开事件名称和完成响应语义。

## 4. 匿名会话与限流

- Cookie：`tcmkg_demo_session`。
- Cookie 属性：`HttpOnly`、`SameSite=Lax`、`Path=/api/v2`，公网部署需启用 `Secure`。
- Cookie 值为随机 UUID，不包含用户或凭据信息。
- 每个 Cookie 使用独立 Redis 会话键，保留最近 5 轮和会话 TTL。
- 同一会话继续使用 Redis 锁，避免并发覆盖历史。
- V2 所有公开路由消耗按 IP 的滑动窗口额度。
- Redis 限流不可用时失败关闭。
- 默认不信任代理头；Nginx 同源部署需显式设置 `GRAPH_QA_TRUST_PROXY_HEADERS=true`。

## 5. 安全边界

- V2 不需要静态 API Key，浏览器不接触静态内部凭据。
- V1 继续要求 `X-API-Key`，原鉴权行为不变。
- V2 REST 错误使用稳定错误码和脱敏消息。
- Tool 路由继续禁止任意 Cypher，不返回原始查询或参数。
- 请求级模型隐藏推理、密钥和数据库连接信息不进入响应。
- OpenAPI 中 V2 路由不声明静态 API Key Security Scheme。
