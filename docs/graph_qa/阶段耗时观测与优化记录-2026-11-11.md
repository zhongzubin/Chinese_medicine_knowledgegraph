# 阶段耗时观测与优化记录

> 验证日期：2026-11-11
>
> 分支：`dev`
>
> 目标：建立端到端阶段耗时基线，并优化占比最高的答案生成阶段

## 1. 实现内容

- LangGraph 的每个节点统一记录内部 `StageTiming`。
- 新增 `answer_with_timings()`，返回原有公开响应和内部阶段耗时轨迹；公开 API 响应和 SSE 字段不变。
- 新增 `graph_qa.latency_evaluate`，输出请求总量和各阶段的 P50/P95、均值、最大值、调用次数和累计占比。
- 对现有受控关系生成中文确定性回答，不再调用回答模型：
  - `HAS_EFFECT`
  - `HAS_INGREDIENT`
  - `TREATS_DISEASE`
  - `ALLEVIATES_SYMPTOM`
  - `HAS_SYMPTOM`
  - `FROM_SOURCE`
- 混合事实、未知关系、聚合、多跳和复杂路径仍使用原模型与证据审核路径。
- 确定性回答继续经过证据覆盖、来源披露和回答审核。

## 5. 当前瓶颈

受控关系回答的 LLM 调用已不再占主要耗时。后续优化应集中在：

1. 实体抽取：当前累计占比 53.9%，主要出现在描述性 semantic 和未知实体问题。
2. 意图识别：当前累计占比 19.2%，部分问题可由更严格的确定性范围规则提前判定。
3. Schema 约束查询规划：当前累计占比 14.9%，长尾受外部模型影响明显。

不应继续优化已经低于 1% 的 Neo4j 查询、Cypher Guard 和确定性证据审核。

## 6. 剩余风险

- 外部模型仍存在格式错误和延迟长尾，单次固定集结果需要结合复跑判断。
- 确定性关系模板只覆盖已列入白名单的关系类型。
- 本次无前端和 API 契约变化，因此未重复浏览器实测。
- 50 条独立人工事实审核结论仍待完成。
