# 证据可追溯中医知识图谱工作台需求规格说明书

> 文档状态：V1.0 设计基线，已确认并进入实施
>
> 编制日期：2026-11-21
>
> 当前代码基线：`847f0e6`
>
> 目标版本：公开演示版 V1

## 1. 背景

当前系统已经具备知识图谱问答、多轮上下文、受控查询、动态多跳、证据审核、CLI、FastAPI、SSE 和 Streamlit 页面。

现有能力的技术深度已经足够，但 Streamlit 页面主要呈现为一个问答界面，用户不容易直接看到：

- 图谱实体之间的关系。
- 多跳路径如何形成。
- 不同药材或方剂之间的差异。
- 回答中的事实如何逐项对应证据。
- 系统如何作为 Tool、Skill 或 MCP 服务被外部 Agent 使用。

因此，本项目需要从“问答页面”演进为“证据可追溯的中医知识图谱工作台”。

## 2. 产品定位

产品面向中医药知识学习、内容核验和关系探索，不提供在线诊断、个性化处方或治疗建议。

核心价值：

1. 答案来自真实 Neo4j 查询结果。
2. 关键事实能够对应节点、关系、属性和来源。
3. 图谱没有依据或来源时明确披露。
4. 复杂问题能够展示确定性的查询计划和逐跳证据。
5. Web、API、Skill 和 MCP 共享同一安全和证据边界。

## 3. 目标用户

| 用户 | 主要需求 |
| --- | --- |
| 招聘方/项目评审者 | 通过公开链接快速理解项目价值和工程深度 |
| 中医药学习者 | 查询和探索方剂、药材、疾病、症状之间的关系 |
| 内容编辑/知识库维护者 | 核验文本中的方剂组成、功效和来源 |
| Agent/开发者 | 通过 Tool 或 MCP 调用图谱证据服务 |

## 4. 产品目标

### 4.1 用户目标

- 无需安装环境即可打开演示链接。
- 能在三次操作内完成一次有价值的问答或图探索。
- 能明确看到回答证据、来源状态和审核结果。
- 模型异常时仍能体验固定演示场景。
- 开发者可以查看 API、Tool、Skill 和 MCP 接入方式。

### 4.2 业务与技术目标

- 将系统从单一聊天界面升级为多入口知识工作台。
- 在不重写安全查询内核的前提下重整前端和应用层。
- 把内部查询能力整理为稳定 Tool。
- 把高频业务组合整理为可评测 Skill。
- 提供本地 stdio MCP Server，为后续远程 MCP 打基础。
- 形成可部署、可演示、可验收的公开版本。

## 5. V1 功能范围

### 5.1 证据问答

- 支持单轮问题。
- 支持最近 5 轮多轮追问。
- 支持属性、关系、聚合、多条件、动态多跳和 Schema 约束查询。
- 通过 SSE 展示公开处理阶段。
- 展示结构化回答、证据、来源和回答审核。
- 模型失败时给出稳定错误或可验证降级。

### 5.2 图谱探索

- 按名称或关键词搜索实体。
- 展示实体身份、标签和基础属性。
- 展示一跳邻居和关系方向。
- 支持按关系类型过滤。
- 支持从当前节点继续探索。
- 展示受控 2～3 步路径。
- 路径节点能够与逐跳证据联动。

### 5.3 实体对比

- 支持两味药材的属性对比。
- 支持两首方剂的组成对比。
- 展示共同项、差异项、来源和来源缺失。
- 对比结果必须能够追溯到图谱证据。

### 5.4 核验与报告

- 展示逐项证据审核结果。
- 展示回答是否被全部证据支持。
- 支持将一次问答或对比结果导出为 Markdown。
- 导出内容包含问题、时间、回答、证据、来源和版本信息。
- 不导出模型隐藏推理、密钥、数据库连接或完整内部日志。

### 5.5 Tool 与 Skill

- 提供只读 Tool Registry。
- 首批工具包含实体解析、属性、邻居、路径、对比、证据审核和来源查询。
- 首批领域 Skill 包含方剂组成核验、多跳关系取证和实体对比。
- Skill 使用声明式配置和工具白名单。
- 不允许 Skill 直接执行任意 Cypher。

### 5.6 MCP 本地接入

- 提供基于 stdio 的 MCP Server。
- 暴露只读 Tools 和只读 Resources。
- MCP Server 调用应用层，不直接连接 Neo4j。
- 提供 MCP 客户端配置样例。
- 远程 MCP 不在 V1 范围内，但接口设计必须允许后续扩展。

### 5.7 演示保护

- 支持固定演示问题。
- 支持匿名短期会话。
- 支持每 IP 限流、并发限制和每日调用预算。
- 外部模型失败时，固定场景仍可完成演示。
- 浏览器端不得包含外部模型或图谱数据库密钥。

## 6. 非目标

V1 不包含：

- 医疗诊断、处方、剂量建议。
- 用户注册、企业多租户和完整权限后台。
- 远程 MCP 公共服务。
- 任意 Cypher 工具。
- 图谱写入、自动补图和在线训练。
- 多 worker 和高可用集群。
- 内容生成、小红书文案或自动发布。
- LoRA、vLLM、模型合并。
- 完整企业监控、审计报表和计费系统。

| FR-03 | SSE 展示公开处理阶段和回答增量 | P0 |
| FR-04 | 回答展示结构证据、来源和审核状态 | P0 |
| FR-05 | 用户可搜索实体并查看一跳邻居 | P0 |
| FR-06 | 用户可查看受控多跳路径及逐跳证据 | P0 |
| FR-07 | 用户可对比两味药材或两首方剂 | P1 |

## 8. 关键用户流程

### 8.1 证据问答

```text
打开页面
-> 选择推荐问题或输入问题
-> 查看实时阶段
-> 查看回答
-> 展开证据、来源和审核结果
-> 继续追问或导出报告
```

### 8.2 图谱探索

```text
搜索实体
-> 打开实体卡片
-> 查看一跳邻居
-> 按关系过滤
-> 选择目标节点
-> 查看受控路径和逐跳证据
```

### 8.3 对比

```text
选择两个实体
-> 查询白名单属性和关系
-> 展示共同点与差异
-> 展开来源
-> 导出对比结果
```

### 8.4 MCP

```text
本地 MCP Client
-> 读取 Schema/Resource
-> 调用实体解析与路径工具
-> 获取结构化证据
-> 由 Agent 基于证据回答
```

## 9. 数据与内容要求

- 实体业务键继续使用 `(label, name)`。
- 对外 API 使用稳定、不透明的实体 ID。
- 所有关系、属性和路径证据必须可序列化。
- 回答中的图谱事实必须引用本轮返回证据。
- 来源缺失必须显式标识。
- 历史会话只保存完成轮次，TTL 在演示模式下可缩短。
- 不保存模型隐藏推理。

## 10. 非功能需求

### 10.1 性能

- 首屏静态资源在正常网络下 2.5 秒内可见。
- 本地页面交互响应不超过 300ms。
- 固定演示问题目标 P95 不超过 15 秒。
- 错误提示必须及时出现，不得无限等待。

### 10.2 可用性

- 支持最新版 Chrome、Edge、Safari。
- 支持电脑和手机宽度。
- 关键状态不只依赖颜色表达。
- 模型失败、无证据和来源缺失都有明确文案。

### 10.3 安全

- 浏览器端无模型密钥、数据库密码和内部 API Key。
- 仅暴露 Web 的 80/443 端口。
- API、Redis 和 Neo4j 不直接暴露到公网。
- 外部输入只进入受控参数。
- Tool 和 MCP 不开放任意 Cypher。

### 10.4 可靠性

- 单个外部模型失败不能导致整站不可用。
- Redis、Neo4j 或模型异常的页面状态必须可区分。
- 服务重启后图谱数据和固定演示场景仍然可用。
- 24 小时连续演示运行无崩溃。

### 10.5 可维护性

- 前后端契约由 OpenAPI 和 Pydantic 模型约束。
- Tool、Skill 和 MCP 使用版本化标识。
- 旧 `/api/v1` 在迁移期保持兼容。
- 历史验收文档保留，文档入口清晰。

## 11. V1 验收原则

V1 必须同时满足：

- 四条主链路：证据问答、图谱探索、实体对比、本地 MCP。
- 六类固定演示场景稳定可复现。
- 现有查询安全边界和证据审核不回归。
- 页面中能够明确看到证据、来源和审核结果。
- 公开演示链接、API 文档和 MCP 示例均可访问。

详细验收项见
[项目验收方案](项目验收方案-2026-11-21.md)。

## 12. 已确认决策

- 前端采用 Vue 3 + TypeScript + Vite。
- V1 使用模块化单体，不拆微服务。
- 保留现有 Neo4j 和查询内核。
- API v1 迁移期保留，新增 API v2。
- MCP v1 使用本地 stdio。
- 远程 MCP、用户注册和企业后台延后。

## 13. 主要风险

- 外部模型调用不稳定。
- 公开演示可能带来模型费用和滥用风险。
- 图谱来源覆盖不完整。
- 旧 Streamlit 与 Vue 并行期间存在契约漂移。
- Tool、Skill 和 MCP 若同时扩张，测试和维护成本会快速上升。

对应控制措施在技术与迁移文档中定义。
