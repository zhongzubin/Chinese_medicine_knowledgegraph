## 2. 主要难点

### 2.1 本地目录遮蔽官方 Neo4j 驱动

**现象**

早期代码位于 `neo4j/` 目录，运行 `python -m neo4j.export_metadata` 时无法加载本地模块，或者可能错误解析到官方 `neo4j` Python 包。

**根因**

本地目录名与项目依赖的官方驱动包完全相同。没有 `__init__.py` 的本地目录会参与命名空间解析，但无法覆盖已安装的常规包。模块路径因此产生歧义。

**处理**

- 将本地目录重命名为 `graph_database/`。
- 更新导入、执行命令、单元测试和 README。
- 验证 `python -m graph_database.export_metadata --help` 可正常执行。

**经验**

项目内部目录不要使用第三方顶层包的名称，尤其是 `neo4j`、`openai`、`langchain` 这类核心依赖名。

### 2.2 元数据只有结构，没有中文语义

**现象**

初始 `graph_metadata.json` 可以说明标签和关系类型，但大模型无法从 `HAS_EFFECT`、`from_source` 等英文名称稳定推断业务含义。

**根因**

Neo4j 只返回属性键和关系类型，不自动提供领域语义；同名属性在不同实体中的含义也没有解释。

**处理**

- 在元数据导出器中维护实体、属性、关系和三元组的中文描述映射。
- 对当前 14 种实际三元组模式分别提供描述。
- 对未来未知字段提供通用中文描述。
- 将描述写入 JSON 和 Markdown 两种元数据文件。
- 将元数据格式版本升级为 `1.1`。

**验证**

- 6 个实体标签、所有属性、6 种关系类型和 14 种三元组模式均有描述。
- 描述缺失数检查结果为 0。
- `grounding` 测试和真实 Cypher 生成均能使用该元数据。

### 2.3 同名实体不能按名称合并

**现象**

`Disease` 和 `Symptom` 中存在大量同名实体，例如“消渴”“风热咳嗽”。如果只按名称匹配，会把疾病和症状混成同一实体。

**根因**

图谱唯一键不是 `name`，而是 `(label, name)`。

**处理**

- 所有链接结果保留 `label`。
- 去重键使用 `(label, name)`。
- 模型给出的 `suggested_label` 只作为排序提示，不再作为硬过滤条件。
- 同名实体同时保留，交由关系模式和问题措辞选择正确目标。

**验证**

- 单元测试覆盖同名 `Disease` / `Symptom`。
- 真实问题“风热咳嗽可以用哪些药材缓解？”最终选择了 `Herb -> ALLEVIATES_SYMPTOM -> Symptom`，而不是错误地查询 Disease。

### 2.4 意图模型会误判图内真实实体

**现象**

真实评测中，“一品红可以治疗哪些疾病？”被模型判断为非中医问题，导致没有进入图谱查询。

**根因**

模型使用了自身对“一品红主要是观赏植物”的一般认知，忽略了它在当前图谱中确实存在 `Herb -> TREATS_DISEASE -> Disease` 关系。

**处理**

- 在调用模型前，先用本地名称/别名索引做确定性预匹配。
- 命中已知图谱实体时，生成 `KNOWN_GRAPH_ENTITY` 意图，直接进入实体链接和查询。
- 未命中已知实体时才调用模型进行意图分类。

**效果**

- 修复了“一品红”误判。
- 减少了一次模型调用。
- 两次完整评测的延迟 P50 从约 6.1 秒下降到约 3.4 秒。该变化也受模型波动影响，不能全部归因于单一优化。

### 2.5 短实体名污染查询

**现象**

“风热咳嗽”最初同时匹配出“风热咳嗽”“咳嗽”“热咳”，导致候选集合包含多个重叠词。

**根因**

名称索引使用子串匹配时，较长实体词天然包含较短的实体词。

**处理**

- 对直接问题匹配执行最长名称优先。
- 如果短词被同一问题中更长的匹配完整包含，则删除短词候选。
- 同名但标签不同的实体仍然同时保留。

**验证**

- “风热咳嗽”只保留 `Disease:风热咳嗽` 和 `Symptom:风热咳嗽` 两个同名异标签候选。
- 真实查询选择了正确的 `Symptom` 关系方向。

### 2.6 提示词生成的 Cypher 不能直接信任

**现象**

大模型可能生成：

- `CREATE`、`MERGE`、`DELETE`、`SET` 等写操作。
- 以分号连接的多条语句。
- `CALL`、`LOAD CSV` 或其他过程调用。
- 变量长度路径。
- 没有 `LIMIT` 的全图查询。
- 元数据中不存在的标签、属性或关系方向。

**根因**

提示词只能降低风险，不能作为安全边界。模型输出是外部不可信数据。

**处理**

实现 `CypherGuard`，在 `EXPLAIN` 和执行前强制检查：

1. 单条语句，且以 `MATCH` 开始。
2. 禁止写操作、注释、反引号、`CALL`、`UNION` 和变量长度路径。
3. 只允许元数据中的标签、属性和关系。
4. 必须包含顶层 `LIMIT`，并限制在 1 到 50。
5. 所有参数必须由计划显式提供。
6. 用户实体名称必须出现在查询参数中。
7. Neo4j 使用只读 access mode，并设置事务超时。
8. 仓储层再次执行安全校验，防止绕过工作流直接调用。

**验证**

- 写操作、多语句、越权标签、未知关系、无 `LIMIT` 和变量长度路径均进入自动化拒绝测试。
- 真实评测的安全用例拦截率为 100%。

### 2.7 查询结果不一定构成可信证据

**现象**

如果模型自行返回 `'Herb' AS subject_label`、`'HAS_EFFECT' AS relationship`，字符串看起来正确，却可能不是数据库中实际节点和关系的值。

**根因**

仅检查别名是否存在，无法证明标签和关系来自真实图路径。

**处理**

- 要求证据字段使用：
  - `subject.name`
  - `labels(subject)[0]`
  - `type(relationship)`
  - `object.name`
  - `labels(object)[0]`
  - `NULL` 或来源节点名称
- 校验每个证据表达式引用的变量属于同一条合法三元组路径。
- 运行时再次验证 `Evidence` 的标签、关系类型和三元组模式。
- 缺少可验证字段时，不把回答标记为 `grounded`。

**验证**

- 伪造常量标签的查询被拒绝。
- 真实 30 条 grounded 回答的证据覆盖率保持 100%。

### 2.8 工作流校验器初始化遗漏

**现象**

首轮工作流测试中，合法查询全部失败并返回 `CYPHER_INVALID`。

**根因**

工作流校验节点引用了未在 `GraphQAEngine` 初始化的 `self.guard`，异常被宽泛兜底为查询校验失败。

**处理**

- 在引擎构造时创建安全校验器。
- 使用仓储层的最大结果数，保证工作流和仓储执行同一限制。
- 添加合法查询的端到端工作流测试。

**验证**

- 修复前 8 条工作流测试中 5 条失败。
- 修复后工作流测试全部通过，并完成真实 Neo4j 查询。

### 2.9 模型输出结构不稳定

**现象**

模型可能返回 Markdown 围栏、额外说明、缺失字段或错误参数类型。

**根因**

自然语言模型不是可靠的 JSON 序列化器。

**处理**

- 所有结构化输出使用 Pydantic 严格模型。
- 格式错误不进入数据库执行。
- Cypher 生成失败最多总共尝试三次。
- 每次重试把上一次的具体校验错误传回模型。
- 三次失败后返回稳定错误码，不递归循环。
- 回答生成失败时，使用图谱证据生成简化兜底回答。

**验证**

- 模型输出格式错误测试保持三次尝试后安全结束。
- 回答模型失败测试仍返回 grounded 证据型回答。

### 2.10 黄金问题集必须对应真实图数据

**现象**

手工设计的评测问题容易包含图谱中不存在的实体、错误的关系方向或不符合预期的标签。

**根因**

评测集的期望必须是可核对事实，不能凭常识填写。

**处理**

- 从现有抽取数据中选取真实实体和关系。
- 用元数据校验 30 条问题的标签和三元组模式。
- 对同名疾病/症状问题记录明确的期望标签。
- 对图谱外问题区分“要求补充实体”和“安全直接回答”。

**验证**

- 30 条用例的实体、标签和关系模式全部存在于当前数据。
- 完整评测无缺失关系模式。

### 2.11 指标口径可能误导

**现象**

只运行前 5 条问题集时，安全用例数量为 0，但汇总曾显示 `safety_rejection_rate=0.0`，看起来像安全能力失败。

**根因**

没有安全样本时把空分母硬编码成 0，混淆了“未评估”和“失败”。

**处理**

- 汇总中增加每类评测样本数。
- 空分母的比率返回 `null`，不再显示为 0。

**经验**

安全指标不能被其他类别稀释，也不能在没有样本时被解释为通过或失败。

### 2.12 非中医回答不应强制显示中医免责声明

**现象**

直接回答量子计算、编程或数学问题时，统一附加“不能替代中医诊断”的免责声明，语义不合适。

**根因**

免责声明应绑定到中医药或健康知识回答，而不是所有文本回答。

**处理**

- 非中医直接回答保留 `grounded=false` 和“未使用图谱证据”提示，但不追加中医免责声明。
- 图谱回答、澄清和无证据的中医问题继续附免责声明。

### 2.13 本地嵌入模型目录被忽略后未被默认配置识别

**现象**

项目已经包含 `models/bge-large-zh-v1.5`，但默认配置仍指向远程 BGE-small，导致误以为需要重新下载模型。

**根因**

`models/` 是本地忽略目录，检查时只看了 Hugging Face 默认缓存，没有检查项目目录；模型路径和默认配置也没有联动。

**处理**

- 默认优先使用项目内 `models/bge-large-zh-v1.5`。
- 相对模型路径以项目根目录解析。
- 本地模型不存在时才回退到远程模型名。
- 新增路径解析回归测试。

**验证**

本地 BGE-large 在完全离线模式下加载成功，输出向量维度为 1024。

### 2.14 语义阈值和词形匹配优先顺序

**现象**

阈值 0.5 时，虚构实体“星辰草”被 FAISS 误匹配到“七星剑”，导致黄金集从 30/30 降到 29/30；同时“麻黄草”的语义 Top-1 是天麻，而字符串 fuzzy 能正确识别麻黄。

**处理**

- 阈值从 0.5 校准为 0.56。
- 匹配顺序固定为“精确名称/别名 → 高置信 fuzzy → FAISS 语义召回”。
- 未知实体分数不足时继续走澄清，不把低置信语义候选当成已知实体。

**验证**

- “星辰草”不再误召回。
- “辛温解表的药材”召回“解表散寒”。
- “能够宣肺平喘的药”召回“清肺平喘”。
- 启用真实 BGE+FAISS 后黄金集恢复 30/30。

### 2.15 全量 FAISS 索引构建无法在每次启动时重复

**现象**

11,043 个实体使用 BGE-large 在 CPU 上首次编码约需 588 秒，不适合每次服务启动重复执行。

**处理**

- 将 FAISS 索引写入 `.cache/graph_qa/faiss/`。
- 缓存键包含实体集合和模型路径。
- 实体或模型变化时自动重建，否则直接加载缓存。

**验证**

缓存文件约 43MB；缓存命中启动约 6.6 秒，FAISS 查询约 0.06 秒。

### 2.16 短实体截获与无关证据 grounded

**现象**

- “空青果”被内部实体“青果”直接命中，模型候选“功效”也可能进入语义召回。
- 模型经常同时列出规范名称和别名，但图中只有规范实体有实际关联。
- 证据与计划目标无关时，原流程仍可能因存在任意证据而标记 `grounded=true`。

**处理**

- 精确预匹配增加问题边界和通用词过滤，预匹配阶段只执行 exact。
- fuzzy 只允许同长度近似词或已知实体后缀的单字符增删。
- 执行查询后过滤与所有计划目标无关的证据；回答前再次执行目标证据校验。
- 目标证据校验采用“至少一个计划目标命中”，避免把规范名/别名同时列入计划时误判无证据。

**验证**

- 50 条 exact 和 20 条 fuzzy 黄金用例 Recall@3 与路径符合率均为 100%。
- 纯召回未知实体误召回从 26.67% 降到 13.33%。
- 完整工作流未知实体误召回从 33.33% 降到 13.33%。
- 全量 120 条 outcome 从 94.17% 提升到 96.67%。
- 未发现 `grounded=true` 且证据与本轮目标完全无关的样本。

### 2.17 专业属性事实存在，但没有进入问答证据链

**现象**

当前图谱已经保存性味、归经、用量、禁忌、主治和用法等专业内容，但本地产品测试中，属性型问题无法稳定得到回答。部分问题即使图谱中存在准确字段，也会在查询规划或 Cypher 安全校验阶段失败。

**根因**

当前工作流以显式关系三元组为主要检索和证据路径：

- `CypherGuard` 要求查询包含 `(s:Label)-[r:TYPE]->(o:Label)` 形式。
- 证据字段要求来自实际节点 `name`、标签和关系类型。
- 只依赖节点属性的查询没有关系变量，无法满足当前证据契约。
- 现有查询提示词限制了用户可控查询的复杂度，属性查询缺少受控模板。

这不是 Neo4j 或模型数据缺失，而是查询层和证据层没有表达属性事实。

**当前数据核对**

2026-10-30 只读检查当前图：

| 对象 | 总量 | 已有字段 |
| --- | ---: | --- |
| `Herb` | 2,359 | 性味 1,466、归经 1,236、用量 1,219、禁忌 851、主治 1,412、功效字段 1,465 |
| `Formula` | 1,020 | 主治 741、功效字段 619、用法 604、禁忌 134 |

“麻黄”节点已有性味、归经、用量、功效、主治和禁忌，说明数据基础可以支持属性问答。当前问题位于产品检索和证据归一化层。

**影响**

- 用户会感觉系统“明明知道却不回答”。
- 现有 120 条评测主要覆盖关系问题，无法暴露属性问题缺口。
- 单纯增加模型能力或扩大图谱规模不能解决该问题。

**后续处理**

按 [product-quality-roadmap.md](product-quality-roadmap.md) 进入“专业问答质量 v1”，首轮已于 2026-10-31 落地：

1. 定义属性证据和关系证据的统一结构。
2. 增加受控属性查询模板。
3. 支持一跳正向、反向和基础聚合。
4. 将属性证据传入回答模型，并在生成后核对事实和引用。
5. 增加属性、无来源和无证据评测。

实现结果：

- `AttributeFact` 和 `facts` SSE 已接入回答与前端。
- 属性白名单查询、一跳正向/反向关系、单跳和多条件计数模板已实现；多条件结果列表仍待后续。
- 回答模型输出增加确定性证据支持检查。
- 10 条属性和 6 条聚合产品集全部 grounded，事实与计数匹配率均 100%。
- 多轮固定集 20 组 62 轮全部通过。

## 3. API、会话和前端实施结果

### 3.1 FastAPI

已实现非流式与 SSE 接口，并包含：

- Pydantic 请求和响应模型。
- 健康检查、组件超时和稳定错误码。
- 多 API Key 鉴权、Redis 限流和全局并发租约。
- 不返回原始数据库异常或模型提示词。

HTTP 层硬取消和完整请求体大小限制仍需由异步模型适配或反向代理补强。

### 3.2 Streamlit

已实现 Streamlit 双栏客户端，并通过真实浏览器验证：

- 左栏展示公开处理阶段，右栏展示流式回答。
- 证据可以展开核对。
- 客户端只显示稳定错误，不显示内部提示词或数据库异常。

### 3.3 会话记忆

当前采用 Redis 轻量会话上下文，而不是保存完整 LangGraph 执行状态：

- 作用域为 `(client_id, session_id)`。
- 保存最近 5 轮问题、回答、已链接实体和 grounded 状态。
- 默认 TTL 为 86400 秒，支持主动删除。
- 同一会话通过 Redis 锁串行执行。
- 不保存 Cypher、查询行、模型提示词和错误堆栈。

静态 API Key 不提供同一客户端内部的端用户身份隔离；正式多用户登录仍需 JWT/OIDC。

### 3.4 流式输出

使用 LangGraph `StreamWriter` 和请求级 SSE：

- `stage` 推送节点级处理进度。
- `answer_delta` 推送答案 token。
- `evidence`、`warning`、`error` 和 `done` 保持稳定事件类型。
- 多 worker/多实例不共享全局用户队列。

不得向前端暴露模型隐藏思维链。

### 3.5 LoRA 微调

微调不是第一版正确性的前置条件：

- 当前已有 120 条评测基线，但 semantic 路径和未知实体误召回仍需改进。
- 没有建立通用模型与微调模型的同集对比前，不能证明微调收益。
- 微调模型仍不能替代 Schema 校验、只读权限和真实证据。

只有在意图或实体抽取成为稳定瓶颈，并且已有独立训练集、验证集和测试集时才进入微调阶段。

## 4. 当前仍然存在的限制

- 黄金集已扩充到 120 条，仍不能覆盖中医药表达的全部歧义。
- 只支持单条固定三元组路径，不支持多跳查询、聚合查询和跨关系复杂问题。
- 属性字段和受控计数已进入统一问答证据；白名单外属性、多条件结果列表和复杂多跳仍待扩展。
- 答案由大模型组织，仍可能出现表述偏差；调用方应展示证据供用户核对。
- 会话只保留最近 5 轮，并绑定 API 客户端而非最终用户。
- 5 轮会话已通过 20 组、62 轮固定集，真实 Redis/API 跨实例测试仍需显式启用。
- 当前使用项目内 `models/bge-large-zh-v1.5`，部署时需要挂载该忽略目录；完整索引缓存到 `.cache/graph_qa/faiss/`。
- 当前本地演示按单 worker 运行；每个额外 worker 会独立加载约 1.3GB 模型和 FAISS 索引。
- 当前本地 BGE-large 校准阈值为 0.56；扩充集已暴露 fuzzy/semantic 误召回，需单独校准。
- 1.1 万实体索引首次构建在 CPU 上约需 10 分钟，后续使用持久化 FAISS 缓存。
- API 层没有可靠终止同步模型调用的硬取消机制。
- Streamlit 仍属于验证界面，不是最终生产前端。
- 没有在线临床验证，不能用于诊断、处方或替代医生。
- 模型供应商或数据库不可用时，只能返回明确错误或证据降级结果。
