## 1. 修订结论

原 V1 同时包含证据问答、图谱探索、实体对比、报告、Tool、Skill、MCP 和公网部署，范围过宽，且 P1 功能仍被验收方案纳入首发门禁。为避免功能持续扩张而长期无法上线，V1 调整为两个分阶段验收的版本：

| 版本 | 目标 | 是否作为首发门禁 |
| --- | --- | --- |
| V1.0 公开演示核心版 | 提供可公开访问、可真实操作、可核对证据的问答与图谱探索核心链路 | 是 |
| V1.1 完整增强版 | 补齐对比、报告、领域 Skill、本地 MCP 和来源增强 | 否 |

V1.0 和 V1.1 都保留现有查询安全、只读执行、证据审核和 `/api/v1` 兼容边界。

## 2. 当前事实基线

本修订基于当前代码和已验证结果，而不是只基于设计文档：

- 当前实现包含 `GraphQAEngine`、受控检索子图、Cypher Guard、只读 Neo4j 仓储、结构化回答审核、FastAPI、SSE、Redis 会话和 Streamlit。
- 2026-11-21 默认全量 pytest 结果为 `275 passed, 5 skipped`。
- 历史验收记录包含 120 条黄金集、220 条产品固定集、20 组 62 轮多轮集和动态多跳固定集结果。
- P5.1 提交上的外部模型固定集尚未重跑，不能把历史指标视为最终提交的实时回归结论。
- 50 条独立领域人工事实审核仍为 `0/50`。
- 公网部署、匿名 Cookie、每日预算和 24 小时连续运行尚未完成。

历史结果用于说明能力基础，不替代当前版本的发布门禁。

## 3. V1.0 公开演示核心版

V1.0 的目标是尽早形成可被陌生用户访问和操作的真实产品，而不是先铺满所有技术模块。

### 3.1 后端范围

- 保留现有 `GraphQAEngine`、检索子图、Cypher Guard、只读仓储和证据审核。
- 保留 `/api/v1` 现有契约、SSE 语义和 Streamlit 回滚入口。
- 增加应用服务、EntityId 映射和只读 Tool 契约。
- 首批 Tool 固定为：
  - `resolve_entity`
  - `query_entity_facts`
  - `query_neighbors`
  - `find_evidence_paths`
- 增加 `/api/v2` 问答、实体搜索、一跳邻居、受控路径和 Tool 发现接口。
- Tool 不接受任意 Cypher，不向调用方返回原始查询行、Cypher 或数据库连接信息。

### 3.2 前端范围

- Vue 3 证据问答页。
- SSE 公开阶段时间线。
- 回答、关系证据、属性事实、路径、来源状态和回答审核展示。
- 实体搜索与一跳邻居探索。
- 受控 2～3 步路径展示及节点、关系与证据联动。
- 未知实体、无证据、来源缺失、模型异常和请求受限状态。
- 手机与桌面布局。
- 最小开发者页面：API 文档入口、首批 Tool 清单和请求示例。

### 3.3 部署范围

- 单 worker、模块化单体、单机 Docker Compose。
- Nginx 提供 Vue 静态资源并代理 API。
- 公网仅开放 80/443，API、Redis 和 Neo4j 不直接暴露。
- 匿名短期会话、每 IP 限流、全局并发和全站模型调用硬上限。
- 健康检查、错误分类、稳定降级和基础运行手册。

首次公网部署安排在问答页和图谱探索页达到可用状态之后，不等 Skill 和 MCP 完成。

### 3.4 V1.0 不阻塞项

- 实体对比。
- Markdown 报告导出。
- 领域 Skill Registry。
- 本地 stdio MCP。
- 远程 MCP。
- 章节、页码、原文片段级来源增强。
- 完整领域人工审核签收。

上述能力可以在 V1.0 发布后继续开发，但相关入口不得用静态假数据伪装为已实现功能。

## 4. V1.1 完整增强版

V1.1 在 V1.0 稳定运行后补齐技术差异化能力：

- 两味药材或两首方剂的对比。
- 问答与对比 Markdown 报告导出。
- `compare_entities`、`audit_claims` 和 `get_source` 等后续 Tool。
- 声明式 Skill Registry 和三个领域 Skill。
- 本地 stdio MCP Server、Resources 和客户端配置样例。
- 来源数据治理与可选来源对象增强。
- 完整固定集重放、人工事实审核和最终发布签收。

V1.1 仍不包含远程公网 MCP、任意 Cypher、图谱写入、多租户、Kubernetes 或多 worker 高可用。

## 5. 关键技术取舍

| 主题 | 本次选择 | 原因 | 后续条件 |
| --- | --- | --- | --- |
| 首发目标 | 先上线核心链路，再扩展功能广度 | 公网访问、真实交互和异常处理比模块数量更能体现工程完成度 | V1.0 稳定后再进入 V1.1 |
| Tool Registry | 保留在 V1.0 | API V2、Vue 和未来 MCP 共用稳定能力边界；后补会导致 API 与前端重写 | Tool 数量继续受 7 个以内约束 |
| Skill Registry | 延后到 V1.1 | Skill 属于任务编排能力，不阻塞问答与探索核心体验 | Tool 契约和固定评测稳定后再实现 |
| 本地 MCP | 延后到 V1.1 | MCP 是差异化接入能力，但不是公开 Web 演示的前置条件 | 应用服务和 Tool 稳定后做薄适配 |
| 实体对比与报告 | 延后到 V1.1 | 增加独立页面、DTO、证据和导出测试，容易分散核心链路投入 | V1.0 已上线且质量门禁稳定 |
| 来源建模 | V1.0 只展示现有 `Source` 和缺失状态，不补造来源 | 当前图谱主要只有来源名称，章节、页码和原文均无可靠数据 | 先完成来源数据盘点、授权和导入设计，再升级结构 |
| EntityId | V1.0 使用 `sha256(label + name)` 内容派生 ID | 可在不修改 Neo4j 的前提下实现同名异标签隔离和可分享 URL | 实体改名会生成新 ID；未来如引入稳定 `uid`，需数据迁移和兼容映射 |
| 降级策略 | 明确区分实时、缓存和确定性降级 | 保持演示真实性，避免把预置答案描述为实时 Agent 查询 | 缓存或确定性路径仍应关联真实图谱证据 |
| 首次部署 | 提前到 V1.0 核心页完成后 | 尽早验证域名、HTTPS、模型成本、内存、网络和陌生用户操作 | V1.1 上线前再执行完整回归与稳定性门禁 |
| 评测数据 | 保持现有固定集，同时优先保证样本质量 | 数据量本身不等于证据，必须保存真实运行结果和失败项 | 新版本必须重跑适用的固定集并归档摘要 |
| 架构表达 | 保留总览图，后续补部署图、问答时序图和 Tool/Skill/MCP 图 | 单图同时表达部署、运行时和扩展关系会导致难以阅读 | 文档和演示材料分别引用最适合的图 |
| 数据授权 | 公网发布前完成来源和再分发检查 | 技术可访问不等于允许公开分发完整数据 | 未确认授权的数据不得进入公网内容 |
| 医疗边界 | 首页和回答区域均展示免责声明 | README 声明不足以覆盖真实用户入口 | 高风险用药问题继续拒绝具体操作建议 |

## 6. 不采纳或缓和的评审建议

### 6.1 不把 Tool Registry 移到第二阶段

Tool Registry 是阶段 1 的稳定契约，不是为展示技术名词而提前实现。若 API V2 先直接调用应用服务，之后再补 Tool 边界，会同时修改 API、前端和测试。

本次保留阶段 1，但限制为首批四个只读 Tool，不提前实现 Skill 或 MCP。

### 6.2 不直接扩展来源字段或修改图结构

增加 `source_id`、章节、页码和原文片段属于数据模型、导入、元数据和评测的实质变化。当前没有可靠数据支持，不能只修改 DTO 就宣称来源可追溯。

本次先在 UI 和 API 中准确展示现有来源与缺失状态，后续再单独完成来源数据治理。

### 6.3 不用更多低质量样本替代现有评测集

现有 120、220 和 62 轮固定集需要继续保留作为回归资产，但发布结论必须来自对应提交上的真实运行结果。新增样本优先覆盖来源缺失、异常降级、浏览器交互和 V2 契约，不以数量增长为目标。

## 7. 验收门禁映射

| 门禁 | V1.0 | V1.1 |
| --- | --- | --- |
| G0 范围与契约冻结 | 必须通过 | 复用并更新 |
| G1 后端与 Tool 契约 | 必须通过 | 增加对比、审核和来源 Tool 检查 |
| G2 核心前端 | 必须通过 | 增加对比和报告页面检查 |
| G3 首次演示部署 | 必须通过 | 增加 V1.1 回归与最终稳定性检查 |
| G4 核心质量签收 | 必须通过 | 在当前提交上重跑 |
| G5 增强能力 | 不阻塞 | 必须通过，包含 Skill、MCP 和来源增强检查 |

详细验收项以[项目验收方案](项目验收方案-2026-11-21.md)为准。

## 8. 变更与回滚

- V1.0 不改变 Neo4j 数据结构，部署回滚不需要数据迁移。
- Vue 出现阻断问题时，可切回已保留的 Streamlit 入口。
- API V2 出现问题时，可关闭 V2 路由并继续使用 `/api/v1`。
- Tool 或应用服务出现回归时，回退对应阶段提交，不影响现有问答内核。
- V1.1 的 Skill 和 MCP 均可独立停止，不影响 Web 核心链路。

## 9. 完成定义边界

任何版本都不得通过以下方式满足验收：

- 使用静态图谱或预置证据冒充实时查询。
- 绕过 Cypher Guard、只读仓储或证据审核。
- 让浏览器接触模型、数据库或内部 API 凭据。
- 把未执行的真实依赖测试标记为通过。
- 把设计文档或历史指标当作当前提交的验收结果。
