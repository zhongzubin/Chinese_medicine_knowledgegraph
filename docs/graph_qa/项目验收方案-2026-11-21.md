## 1. 验收目标

验证系统是否达到：

- V1.0：可公开访问的 Vue 证据问答、图谱探索、只读 Tool 和真实部署。
- V1.1：可核验的实体对比与报告，以及 Tool、Skill 和本地 MCP 的完整接入。
- 两个版本均保持现有安全和质量能力不回归。

验收不以页面“看起来完成”为标准，而以真实链路、结构化证据、异常处理和可重复验证为准。

首次公网部署可以先形成带明确版本标识的 V1.0 Preview；只有 G0～G4 全部通过后，才能宣布 V1.0 正式完成。

## 2. 验收环境

- Node.js 与前端锁定依赖。
- pytest。

### 2.2 真实依赖环境

- Redis。
- 本地 BGE 模型。
- 可用的外部模型接口。
- 真实 FastAPI 和 Vue 构建产物。

### 2.3 演示环境

- HTTPS 公网域名。
- 单 worker API。
- Vue 静态资源。
- Redis。
- Neo4j。
- 匿名演示 Cookie 和限流。

## 3. 验收角色

| 角色 | 职责 |
| --- | --- |
| 开发者 | 功能、测试、部署和缺陷修复 |
| 项目负责人 | 范围、优先级和最终发布确认 |
| 领域审核者 | 50 条人工事实结论和医疗内容边界 |

## 4. 发布门禁

V1.0 正式完成需要 G0～G4 全部通过；V1.1 完成需要 G0～G5 全部通过。首次公网可用早于正式完成，但只能标记为 V1.0 Preview。

### G0：需求与架构冻结

必须满足：

- 需求、架构、迁移和验收文档评审通过。
- V1.0 与 V1.1 的发布范围、阻塞项和非目标明确。
- Vue 3、首批四个 Tool、Skill 和 stdio MCP 分别归入正确版本。
- 非目标清晰。
- 主要取舍记录在统一文档中。

### G1：后端与契约

必须满足：

- 现有 pytest 全量通过。
- `/api/v1` 核心契约不回归。
- V1.0 `/api/v2` 核心契约测试和 OpenAPI 生成通过。
- 四个首批 Tool 的输入输出、超时和错误测试通过。
- EntityId 在同一实体集合上确定且同名不同标签不冲突。
- Tool 返回领域 DTO 和证据，不返回原始 Cypher、查询行或凭据。

阻断条件：

- 任意 Tool 能提交原始 Cypher。
- V2 绕过 Guard 或证据审核。
- 前端能从响应获取密钥。

### G2：前端核心页面

必须满足：

- V1.0 证据问答、图谱探索和审核联动可操作。
- 加载、空、错误、无证据和来源缺失状态完整。
- 手机和桌面布局通过浏览器测试。
- 浏览器中不存在模型或数据库凭据。
- 页面交互真实请求 V2 后端，不使用静态图谱或预置证据代替实时查询。

阻断条件：

- 关键页面只在桌面可用。
- 图谱探索渲染完整图或递归失控。
- 回答与证据无法联动。

### G3：V1.0 首次部署

必须满足：

- 公网 HTTPS 链接可访问。
- 只有 80/443 对外。
- 匿名会话、限流、并发和全站模型调用硬上限有效。
- 健康检查、日志、自动重启和回滚入口有效。
- 实时、缓存和确定性降级模式在界面可区分。

阻断条件：

- 数据库或模型密钥进入前端构建产物。
- API、Redis 或 Neo4j 端口直接暴露公网。
- 无全站模型预算限制。
- 使用预置答案冒充实时 Agent 查询。

### G4：V1.0 质量签收

必须满足：

- 固定演示问题、未知实体、无证据、来源缺失和模型失败场景全部通过。
- 当前适用的 Python、Vue、API V2 和浏览器测试通过。
- 现有查询安全、多轮和证据审核无不可接受回归。
- V1.0 适用的固定集在当前提交上执行并通过。
- 24 小时连续运行通过。

阻断条件：

- 安全阻断项未解决。
- 使用历史指标代替当前提交的测试结果。
- 真实依赖故障被伪装为通过。
- 必需固定集因外部依赖不可用而处于 `blocked` 或 `not_evaluated`。

### G5：V1.1 增强能力

必须满足：

- 实体对比和报告可操作、可追溯且不泄露敏感信息。
- 三个 Skill 使用白名单 Tool。
- Skill 达到调用次数或超时后安全终止。
- stdio MCP 客户端可以发现 Resources 和 Tools。
- MCP 返回结构与 Web API 证据语义一致。
- 来源增强经过数据授权和真实性检查。
- 50 条人工事实审核完成并达到门槛。
- 完整固定集在当前提交上重跑并保存结果。

阻断条件：

- MCP 直接连接 Neo4j。
- Skill 可以调用未声明的 Tool。
- MCP 暴露任意 Cypher。
- 对比或报告使用无法追溯的来源或隐藏推理。
- 未评估项被标记为通过。

## 5. 功能验收用例

### 5.1 证据问答（V1.0）

| 编号 | 输入/操作 | 预期 |
| --- | --- | --- |
| QA-01 | 询问麻黄功效 | 返回回答、属性或关系证据、来源状态和审核 |
| QA-02 | 询问含麻黄方剂 | 返回关系列表和逐项证据 |
| QA-03 | 询问动态多跳问题 | 返回完整 2～3 步路径和逐跳证据 |
| QA-04 | 多轮追问“它有什么禁忌” | 正确继承上一实体 |
| QA-05 | 询问未知实体 | 请求补充，不执行无依据查询 |
| QA-06 | 已知实体但无证据 | 明确说明图谱无依据 |
| QA-07 | 来源缺失问题 | 显示“当前图谱未提供出处” |
| QA-08 | 模型偶发失败 | 显示稳定降级，不暴露堆栈或密钥 |

### 5.2 图谱探索（V1.0）

| 编号 | 输入/操作 | 预期 |
| --- | --- | --- |
| EX-01 | 搜索四君子汤 | 返回方剂实体和基础信息 |
| EX-02 | 展开一跳邻居 | 返回组成药材和来源关系 |
| EX-03 | 只保留组成关系 | 其他关系被过滤 |
| EX-04 | 点击药材继续探索 | 以新实体为当前节点继续查询 |
| EX-05 | 查询多跳路径 | 高亮节点链、关系方向和逐跳证据 |
| EX-06 | 超过结果上限 | 显示限制提示，不渲染全图 |

### 5.3 实体对比（V1.1）

| 编号 | 输入/操作 | 预期 |
| --- | --- | --- |
| CP-01 | 对比麻黄与桂枝 | 展示共同属性和差异属性 |
| CP-02 | 对比麻黄汤与桂枝汤 | 展示共同药材和差异药材 |
| CP-03 | 无来源字段 | 对比表中明确标识 |
| CP-04 | 对比不存在的实体 | 请求澄清或返回稳定空状态 |

### 5.4 报告（V1.1）

| 编号 | 输入/操作 | 预期 |
| --- | --- | --- |
| RP-01 | 导出问答报告 | Markdown 包含问题、回答、证据、来源、审核、时间 |
| RP-02 | 导出对比报告 | 包含共同项、差异项和证据 |
| RP-03 | 检查敏感字段 | 不包含密钥、数据库信息和隐藏推理 |

### 5.5 Skill（V1.1）

| 编号 | Skill | 预期 |
| --- | --- | --- |
| SK-01 | 方剂组成核验 | 仅调用白名单工具，输出逐项核验 |
| SK-02 | 多跳关系取证 | 输出完整路径和审核结果 |
| SK-03 | 实体对比 | 返回结构化对比和来源 |
| SK-04 | 超过调用上限 | 安全终止并返回稳定原因 |

### 5.6 MCP（V1.1）

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| MC-01 | 列出 Resources | 返回 Schema、评测和使用说明 |
| MC-02 | 列出 Tools | 返回 5～7 个只读工具及 Schema |
| MC-03 | 调用实体解析 | 与 Web API 返回一致 EntityRef |
| MC-04 | 调用路径工具 | 返回 PathEvidence 和来源 |
| MC-05 | 非法参数 | 返回结构化参数错误 |
| MC-06 | 尝试任意 Cypher | 工具不存在或请求被拒绝 |

## 6. 安全验收

必须验证：

- 前端构建产物不包含 `.env`、模型 Key、Neo4j 密码、Redis 密码。
- 浏览器网络请求中不出现静态内部 API Key。
- Neo4j 使用只读账号。
- 用户参数只进入查询参数。
- 写操作、多语句、变量长度路径和未授权关系被拒绝。
- Markdown 渲染无法执行脚本。
- 图谱 SVG/Canvas 文本不会注入 HTML。
- 限流和每日预算在并发请求下仍有效。
- 日志不记录完整健康问题和模型提示词。
- 首页和回答区域展示医疗使用边界。
- 公网发布前完成图谱数据来源、引用方式和再分发授权检查。
- 实时、缓存和确定性降级模式不会被混淆。

阻断级安全问题：

- 任意 Cypher 执行。
- 数据库写操作。
- 密钥泄漏。
- 跨会话读取。
- XSS 或任意 HTML 执行。

| 本地 UI 交互响应 | ≤ 300ms |

| --- | --- | --- |

### 7.3 演示容量

最低验证：

- 10 并发用户。
- 50 个连续固定问题。
- 一个会话完成 5 轮追问。
- 连续运行 24 小时。

## 10. 部署验收

### 10.1 V1.0 首次部署

- `compose.demo.yml` 可在干净环境启动。
- 服务重启后数据仍在。
- 健康检查能区分 API、Redis 和 Neo4j 状态。
- Nginx 仅暴露 80/443。
- HTTPS 证书有效。
- 日志可定位 request_id 和错误类型。
- 每日模型预算达到后停止新增模型请求并给出降级提示。
- 回退上一镜像版本后服务可恢复。
- 首次部署可以早于 V1.1 完成，但必须标识为 V1.0 Preview；G4 通过后才能宣布 V1.0 正式完成。

### 10.2 V1.1 最终部署

- 重新执行 V1.0 部署门禁。
- 对比、报告、Skill 和 MCP 入口可独立关闭。
- 来源增强、固定集和人工审核结论已归档。
- 连续运行 24 小时且无阻断错误。

## 12. 已知风险与豁免

以下情况不能直接豁免：

- 外部模型不稳定。
- 人工事实审核未完成。
- 安全阻断项。
- 数据来源无法披露。
- V1.0 正式签收时固定集未执行或结果不明。

可记录为观察项：

- 外部模型 P95 波动。
- 首次 BGE 加载时间。
- 单 worker 容量上限。
- 远程 MCP 未实现。
- 企业用户体系未实现。
- V1.0 Preview 已上线但尚未完成正式质量签收。
