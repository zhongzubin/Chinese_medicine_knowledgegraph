## 3. 人工审核填写规则

审核者需要逐条填写：

- `review_status`：`completed`。
- `fact_verdict`：`correct`、`partial` 或 `incorrect`。
- `unsupported_claims`：回答中不能被本轮证据支持的事实；没有则为空数组。
- `source_disclosure_correct`：来源展示或“当前图谱未提供出处”是否明确正确。
- `reviewer_role`：审核者角色，不填写个人信息。
- `review_notes`：必要的简短说明，不记录账号、联系方式等个人数据。

审核文件不包含自动期望结果，避免审核者被生成标签锚定。测试集已有答案、
自动匹配结果或审核工具的通过状态均不能代替独立领域人工结论。

## 5. 基础 CI

工作流文件：

```text
.github/workflows/ci.yml
```

触发条件：

- push 到 `main` 或 `dev`。
- 面向 `main` 或 `dev` 的 pull request。
- 手动触发。

功能分支只通过 pull request 检查，避免同一提交同时产生 push 和
pull request 两次重复运行。

执行内容：

```text
uv python install 3.12
uv sync --frozen
uv run python -m pytest tests/ -v
```

运行单元测试时注入 `MODEL_API_KEY`、`MODEL_BASE_URL` 和 `MODEL_NAME`
占位变量。它们只用于满足旧抽取模块在导入阶段创建客户端对象的配置要求，
当前单元测试不会向该地址发送请求。

CI 只读仓库内容，不读取项目密钥，不连接 Neo4j、Redis 或外部模型。
真实依赖集成测试继续显式启用：

```powershell
$env:GRAPH_QA_RUN_INTEGRATION = "1"
$env:GRAPH_QA_RUN_API_INTEGRATION = "1"
$env:GRAPH_QA_REDIS_TEST_URL = "redis://127.0.0.1:6379/0"
uv run python -m pytest tests/ -v
```

默认 CI 的完成标准是全量 pytest 通过。真实 Redis/API/Neo4j 集成的可重复
运行环境需要后续单独配置，不能因为基础 CI 通过就宣称真实依赖 CI 已完成。
