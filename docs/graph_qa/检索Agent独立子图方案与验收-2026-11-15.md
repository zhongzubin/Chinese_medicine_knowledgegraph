## 1. 目标

将当前直接位于主图中的四个检索阶段：

```text
plan_cypher
validate_cypher
execute_cypher
retrieve_observe
```

收敛为一个独立、可单独测试和演进的 LangGraph 检索子图，同时保持现有产品行为不变。

完成后的主链路仍为：

```text
实体链接
  -> 检索子图
  -> 图谱回答 / 无依据 / 安全失败
  -> 回答审核
```

## 2. 改造前事实

- 改造前主图有 17 个固定节点。
- `RetrievalAgent` 已承担 `plan` 和 `observe` 决策。
- 查询校验、Guard、`EXPLAIN` 和仓储执行仍由 `GraphQAEngine` 的确定性代码完成。
- 主图当前直接在节点之间维护 `plan_cypher → validate_cypher → execute_cypher → retrieve_observe` 条件循环。
- SSE、CLI、API 和 Streamlit 已依赖 `plan_cypher`、`retrieve_observe` 等公开阶段名称。
- 当前最多执行三次规划和观察循环。

## 3. 本次范围

包含：

- 新增独立检索子图构建器。
- 将规划、校验、执行和观察编排移入子图。
- 保持现有 `AgentState`、查询计划模型和公开响应结构兼容。
- 保持内部阶段名称、顺序、Agent 归属和流式事件可用。
- 增加子图自身、嵌套流式输出和主工作流回归测试。
- 完成真实 API/SSE、Neo4j 和浏览器回归验证。

不包含：

- 动态调度多个 Agent。
- 完全自治协作或由模型选择任意工具。
- 新增查询类型、关系路径或聚合模式。
- 修改 Cypher Guard、只读执行、权限和证据审核规则。
- 改变 API、SSE、CLI 或前端公开字段。
- 性能优化、多 worker、内部试用或部署工程化。

## 4. 架构边界

### 4.1 子图职责

检索子图只负责编排：

```text
plan -> validate -> execute -> observe
                    ^           |
                    |-- replan -|
```

终止决策保持为：

- `answer_from_graph`
- `no_evidence`
- `safe_fail`
- `finish`

子图不得：

- 直接接受模型自由生成的 Cypher。
- 绕过 Schema 校验、Guard 或 `EXPLAIN`。
- 读写 Neo4j 或 Redis 连接配置。
- 生成最终医疗事实。
- 修改回答审核结果。

### 4.2 依赖注入

检索子图通过注入的运行时能力调用现有确定性组件：

- `RetrievalAgent.plan`
- 查询计划校验函数
- `GraphQAEngine` 提供的执行回调
- `RetrievalAgent.observe`

Guard、仓储和 Schema 的所有权仍属于 `GraphQAEngine`。子图不成为数据库或安全策略的所有者。

### 4.3 状态兼容

继续使用现有 `AgentState` 字段，不新增公开响应字段：

- `retrieval_plan_kind`
- `retrieval_steps`
- `retrieval_next_action`
- `retrieval_trace`
- `query_attempts`
- `validation_errors`
- `last_error_code`

如内部需要子图专用状态，只能作为不进入 API 响应的私有结构。

## 5. 主图集成

主图增加一个检索入口，用于运行已编译子图：

```text
link_entities
  -> retrieval_subgraph
       -> answer_from_graph
       -> no_evidence
       -> safe_fail
       -> finish
```

要求：

- 不新增用户可见阶段名称。
- 子图内部的 `plan_cypher`、`validate_cypher`、`execute_cypher` 和 `retrieve_observe` 继续按原顺序流式输出。
- 子图外层包装节点不得产生重复 `stage` 事件。
- `stage_timings` 继续记录内部阶段，不新增无法归因的重复耗时。
- 非流式 `invoke` 和流式 `stream` 必须得到相同的最终状态。

## 7. 测试要求

### 7.1 子图单元测试

- 正常计划一次执行后进入 `answer_from_graph`。
- 校验失败后可重规划，达到上限后进入 `safe_fail`。
- 属性为空可进入关系回退重规划。
- 空结果进入 `no_evidence`。
- 执行异常进入稳定失败路径。
- 循环次数不超过三次。
- 不得创建子图之外的查询计划或工具。

### 7.2 主工作流测试

- 主图能正确调用子图并取得最终状态。
- 非流式和流式最终回答一致。
- 公开阶段顺序与当前行为一致。
- SSE `stage` 的 `agent`、`plan_kind`、`decision` 和 `reason_code` 不缺失。
- 属性、聚合、多条件、动态多跳、受控关系和 Schema 约束回退均不回归。
- 未知实体、无依据和安全失败路径不回归。

### 7.3 真实依赖与页面

- 真实 Neo4j 只读查询成功。
- FastAPI 非流式响应和 SSE 事件完整。
- Streamlit 可展示检索规划、观察决策、证据和回答审核。
- 至少完成一次属性重规划链和一次正常回答链的浏览器验证。

## 9. 风险与回滚

主要风险：

- 嵌套子图的更新流可能丢失或重复公开阶段。
- 父子图状态合并可能覆盖重规划字段。
- 条件边迁移可能改变错误终止路径。
- 阶段耗时可能被重复统计。

控制措施：

- 先完成子图单元测试，再接入主图。
- 使用现有状态字段并增加事件顺序断言。
- 对每次循环记录稳定 `reason_code`。
- 保留集成前提交作为回滚点，不涉及数据库迁移。

回滚方式：

1. 回退主图集成提交，恢复四个节点的主图实现。
2. 保留独立子图测试作为后续开发基础，不修改图数据库。

- 最新 `main` 或 `dev` 的基础 CI 已确认通过。
