# 语义召回边界验证记录

> 验证日期：2026-11-09
>
> 分支：`dev`
>
> 目标：修复描述性 semantic 候选被错误标签和高分短词抢占的问题

## 1. 问题与根因

真实模型对“哪些方剂能清除体内热毒？”返回：

- `清除体内热毒`：建议标签 `Effect`
- `热毒`：建议标签 `Disease`
- `方剂`：建议标签 `Formula`

原实现只取全局 FAISS Top-3，三个结果均为 Disease，导致查询被规划为
`Formula -TREATS_DISEASE-> Disease`，最终无证据。

本轮确认了两个独立问题：

1. 描述性 semantic 候选没有使用模型建议标签约束。
2. 较短子串候选“热毒”会追加不同标签的语义结果，污染较长描述候选。

## 2. 实现内容

- `SemanticEntityIndex.match()` 支持可选 `labels` 和 `candidate_limit`，
  可在更大 FAISS 候选集合中按目标标签过滤，默认行为保持不变。
- 描述性 semantic 候选优先使用 `suggested_label` 召回。
- 标签过滤没有结果时回退全局 semantic Top-3，兼容模型标签提示错误的情况。
- 较长描述候选得到 semantic 结果后，跳过其包含的较短子串候选。
- 精确同名实体仍不受建议标签硬过滤。
- 未知具体实体仍不能仅凭 semantic 匹配通过。

## 6. 剩余风险

- 模型建议标签仍可能错误；本轮通过标签优先、无结果回退控制影响，但不能保证所有
  新表达都命中。
- semantic path match 仍有少部分 fuzzy/semantic 路径差异，需要后续扩充独立问题集。
- P95 延迟仍较高，本轮未进行阶段级性能优化。
- 50 条独立人工事实审核结论仍待完成。
