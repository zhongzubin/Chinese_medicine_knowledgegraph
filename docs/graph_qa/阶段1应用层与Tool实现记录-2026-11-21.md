## 1. 实现范围

阶段 1 在不修改 `GraphQAEngine`、`CypherGuard`、证据审核和 `/api/v1` 行为的前提下，增加：

- 图谱证据应用服务。
- 内容派生 EntityId 和反向映射。
- 版本化只读 Tool 契约。
- Tool Registry 和 Executor。
- 四个首批只读 Tool。
- 受控一跳邻居只读仓储查询。
- Tool、EntityId、邻居查询和错误边界单元测试。

## 2. 新增模块

| 模块 | 职责 |
| --- | --- |
| `graph_qa/application/entity_ids.py` | 根据 `(label, name)` 生成不透明 EntityId，支持反向解析 |
| `graph_qa/application/contracts.py` | EntityRef、实体解析、属性、邻居和路径 DTO |
| `graph_qa/application/graph_evidence_service.py` | 复用现有仓储、Schema 和 EntityIndex 提供四个只读能力 |
| `graph_qa/tools/contracts.py` | ToolDefinition、ToolResult、结构化错误和执行上下文 |
| `graph_qa/tools/registry.py` | 按工具 ID 和语义版本注册、发现和选择 Tool |
| `graph_qa/tools/executor.py` | 参数校验、独立超时、结果上限和异常脱敏 |
| `graph_qa/tools/catalog/graph_evidence.py` | 注册四个首批只读 Tool |
| `graph_qa/neo4j_repository.py` | 增加受控 `execute_neighbors()` 只读查询 |

## 3. 首批 Tool

| Tool | 输入 | 输出 |
| --- | --- | --- |
| `resolve_entity` | 查询文本、可选标签提示和数量 | 带 EntityRef 的实体候选 |
| `query_entity_facts` | EntityId 和可选属性列表 | 白名单属性事实、来源和可用属性 |
| `query_neighbors` | EntityId、可选关系、方向和上限 | 一跳邻居、相对方向和关系证据 |
| `find_evidence_paths` | EntityId 和 2～3 步关系/目标标签 | 受控路径和逐跳证据 |

Tool 输入输出均为 Pydantic DTO。Tool 不接受任意 Cypher，不返回原始查询行、Cypher、参数或数据库连接信息。

## 4. 安全与边界

- EntityId 同名不同标签会生成不同 ID。
- EntityId 是内容派生 ID；实体改名后会变化，不作为永久业务身份键。
- 邻居查询只接受 Schema 中的标签、关系方向和三元组模式。
- 路径 Tool 只接受 2～3 步、连续、不重复标签和关系类型的 Schema 路径。
- Executor 对 Tool 执行设置独立超时和结果上限。
- 未找到 Tool、非法参数、未知实体、超时和执行失败均返回结构化错误。
- 应用服务可通过 `GraphEvidenceService.from_engine()` 复用现有 Engine 的只读依赖。
